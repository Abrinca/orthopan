# OrthoPan development handbook

For a developer or agent continuing this work. Practical, not exhaustive.

## Project status

OrthoPan is a two-step pipeline plus a browser viewer. `orthopan import` turns an OrthoFinder
results directory or a plain orthologs TSV into a processed directory of Parquet + Numpy files
(genome tree, bit-packed presence matrix, per-orthogroup tracks, annotations, genome metadata,
and optional single-orthogroup detail sources). `orthopan serve` is a FastAPI backend that serves
windowed matrix/track/annotation slices and per-orthogroup MSA, gene tree and sequences to a deck.gl
UI. The UI is a linear heatmap with search, annotations, genome metadata and a full-screen alignment
view. Read `README.md` for the user-facing tour, `VISION.md` for the intent, and
`docs/design-decisions.md` for *why* the pipeline is shaped this way. `docs/api.md` is the backend
contract; `docs/implementation.md` is the deeper implementation narrative.

## Environment

- **Python 3.14 via [uv](https://docs.astral.sh/uv/)**. `.python-version` is `3.14` and
  `pyproject.toml` pins `requires-python = "==3.14.*"`. Do not bump to 3.15: polars' Series
  dispatch is broken there (see `docs/design-decisions.md` §Interpreter).
  Use `uv run …` for everything so the pinned interpreter and lockfile are used.
- **bun for the web UI only** (`web/`; Vite + TypeScript + deck.gl, no React). There is no Node
  in this environment. `cd web && bun install`, then `bun run dev`, `bun run build`, `bun test`.
- **OrthoFinder environment** lives in the gitignored `scratch/.venv` (Python 3.12.15). Its bundled
  FAMSA binary is at `scratch/.venv/lib/python3.12/site-packages/orthofinder/bin/famsa`; pass it to
  `orthopan serve --famsa PATH`, or put `famsa` on `PATH`. The scripts that produced the demo
  resources are in `scripts/orthofinder/` (`run_core_assign.sh`, `run_core_podman.sh`).
- `resources/` is read-only and gitignored; never edit it. `scratch/` is gitignored working space.

## Data

### Sources (under `resources/`, read-only + gitignored)

- `resources/orthofinder-demo/`: a 24-genome OrthoFinder run. `results/Results_Oct04` is the core
  run (17 genomes), `results/Results_Oct04_1` is the `--assign` run on the same 24 genomes, and
  `results-full-24/Results_Oct04` is a full 24-genome run. `faa-core` (17) and `faa-add` (7) hold
  the protein FASTAs. The species tree used by the trees is
  `results/Results_Oct04_1/Species_Tree/SpeciesTree_rooted.txt`.
- `resources/large-dataset/orthologs.tsv.gz`: a real OrthoFinder v3 output, 2,193 genomes ×
  50,515 orthogroups. No tree or tracks ship with it.
- `tests/data/`: gitignored; `scripts/build_datasets.sh hog` downloads `orthologs.tsv` (Format A) and
  `orthologs-descriptions.tsv` (real descriptions) from `demo.abrinca.com` when they are missing.
  `tests/conftest.py` holds the same URLs in the `test_data` fixture, which no current test requests.
- `scripts/simulate_pangenome.py`: seeded simulator writing a rooted tree, a Format B orthologs
  TSV (gzip), annotations and genome metadata. Deterministic per `--seed`.

### Built datasets (`scratch/datasets/`, gitignored, rebuilt by `scripts/build_datasets.sh`)

| Dataset | Source | Genomes × OGs × genes | Exercises | Build |
| --- | --- | --- | --- | --- |
| `demo` | `Results_Oct04_1` + synthetic genome metadata | 24 × 5,657 × 51,887 | OrthoFinder MSAs, gene trees, OrthoFinder tracks; on-demand FAMSA for OGs without an MSA (e.g. `OG0002832`, 3 genes) | ~2 s |
| `hog` | `tests/data/orthologs.tsv` (Format A) + real descriptions + demo tree + `--fasta` core/add | 24 × 6,553 × 51,886 | Format A gene→genome mapping, real text annotation, byte-offset FASTA index | ~1 s |
| `large` | `resources/large-dataset` + UPGMA tree (`orthopan-tree`) + synthetic annotations/metadata | 2,193 × 50,515 × 5,108,661 | a real ~2k-genome matrix | ~14 s |
| `sim10k` | `scripts/simulate_pangenome.py` 10,000 × 50,000 + generated tree/annotations/metadata | 10,000 × 50,000 × 25,131,506 | 10k-scale import and serve (24.4M present cells) | ~66 s |

`large` and `sim10k` include 8-clade `clade` + numeric `gc` genome metadata and synthetic
`description` (text) + `cog_category` (categorical) annotations, generated by
`scripts/make_test_metadata.py`. `demo` gets only the genome metadata; `hog` uses the real
descriptions. On-disk sizes: demo 0.7 MB, hog 1.2 MB, large 66 MB, sim10k 340 MB. sim10k is about
13 s simulating + 52 s importing.

## Running

```sh
scripts/build_datasets.sh                 # all four
scripts/build_datasets.sh demo hog        # any subset: demo hog large sim10k
```

The script removes and rebuilds each target (and its `*-input/` directory), so it is idempotent. All
requested names are validated up front; each dataset's required inputs are checked before its
existing output is deleted, and `hog` downloads
`tests/data` from `demo.abrinca.com` when it is not present.

Serve a built dataset (the server serves the built UI from `src/orthopan/static`, or falls back to
`web/dist`; that static directory is gitignored, built locally from `web/`, and included in the
wheel and sdist):

```sh
uv run orthopan serve scratch/datasets/demo  --port 8001 --famsa scratch/.venv/lib/python3.12/site-packages/orthofinder/bin/famsa
uv run orthopan serve scratch/datasets/hog   --port 8001 --famsa scratch/.venv/lib/python3.12/site-packages/orthofinder/bin/famsa
uv run orthopan serve scratch/datasets/large --port 8001
uv run orthopan serve scratch/datasets/sim10k --port 8001
```

`--famsa` only matters for `demo` and `hog`: they carry sequences but not an MSA for every
orthogroup, so those are aligned on demand. Without famsa, `GET /api/orthogroup/{og}/msa` returns
404 for OGs that have no shipped MSA. Quick check: `curl -s localhost:8001/api/meta`, and for demo
`curl -s localhost:8001/api/orthogroup/OG0000000/msa` and `…/gene-tree`.

Frontend dev loop:

```sh
uv run orthopan serve scratch/datasets/demo        # backend on :8000
(cd web && bun run dev)                            # Vite dev server, /api proxied to :8000
(cd web && bun run mock)                           # mock API on :8000, no backend needed
(cd web && bun run build)                          # rebuild the UI into src/orthopan/static
```

## Testing

```sh
uv run pytest -q -W error
(cd web && bun test && bun run build)
```

`bun run build` rewrites the gitignored `src/orthopan/static`, so run it only when you mean to
update the locally served UI. Tests that need `resources/` skip with a reason when it is absent;
`ORTHOPAN_TEST_NO_RESOURCES=1 uv run pytest -q -W error` exercises those skips. Browser QA: the
Playwright MCP cannot launch Chrome in this environment; agents used
`playwright-core` driven from a bun script with `/usr/bin/chromium-browser`. Uncommitted examples
are in `scratch/vision-qa/` (e.g. `v2-check.ts`, `scale10k.ts`).

## Workflow conventions

- Keep throwaway scripts, smoke outputs and logs in a per-task `scratch/<task>/` subdirectory
  (AGENTS.md). Never write under `/tmp`; `resources/` is read-only.
- A reviewer checks every change before it is committed; verify with real commands (tests, build,
  a brief `orthopan serve`) before declaring done.
- Commit messages are short imperative summaries (e.g. `Add annotations …`, `Scale backend to 10k …`).
- Do not edit `pyproject.toml`, `.python-version` or `uv.lock` casually: the Python pin (3.14, not
  3.15) and locked deps matter.
- The dataset **`format_version` gate**: `Pangenome` rejects any imported directory with
  `format_version < 2`. If you change the on-disk format, bump `FORMAT_VERSION` in
  `src/orthopan/importer.py` and re-run `scripts/build_datasets.sh` for every dataset.

## Open items and ideas

- Copies-mode full-screen matrix at 10k is ~92–121 ms against a 100 ms target.
- FAMSA is an external install; it is only bundled in the local `scratch/.venv` OrthoFinder
  environment, so on-demand alignment needs `--famsa PATH` (or `famsa` on `PATH`).
- OrthoFinder leaves ~2% of small (2–3 gene) orthogroups without an MSA; cause unresolved
  (`docs/design-decisions.md`).
- Deferred UX: a split view so the matrix stays visible next to the drawer; linking tree leaves to
  MSA rows is already done in the alignment view; an alignment minimap is already covered by the
  overview strip.
- Nothing has been tested on a **real** 10k dataset — `sim10k` is simulated and `large` is 2,193
  real genomes.
- `uv build --sdist` was verified to include the built UI under `src/orthopan/static`, so the
  earlier worry that the sdist lacked the UI is resolved.
